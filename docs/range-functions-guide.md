# Range Functions Guide

Range functions turn document analysis into composable geometry. A source produces ranges; a transformer receives a source and returns a new generator; a combiner evaluates several sources as one.

```text
source -> transformer -> transformer -> generated ranges
```

This guide explains how to choose and compose those pieces. See [Range Functions Reference](range-functions-reference.md) for exact signatures and edge cases.

## Sources, transformers, and combiners

A range source is either an iterable or a generator:

```js
const staticSource = [[0, 5], [10, 15]];

function generatedSource(document, createRange) {
    for (const match of document.matchAll(/\d+/g)) {
        createRange(match.index, match.index + match[0].length);
    }
}
```

Built-in sources adapt common inputs:

- `rangesForMatch()` scans the document for a string or regular expression.
- `rangesForLines()` produces complete lines, line content, newlines, or boundary points.
- `rangesFrom()` adapts raw input, document boundaries, or an options-style range producer.
- `rangesFromLayer()` reuses ranges generated by an earlier named layer.
- `rangesFromOptions()` reads a source from render options.

A transformer is curried. Configure it first, then apply it to a source:

```js
const expandByOneLine = applyExpandTo('line', 1);
const expandedMatches = expandByOneLine(rangesForMatch(/ERROR/g));
```

`rangesCompose()` makes a multi-step transformation read from left to right:

```js
rangesCompose(
    rangesForMatch(/ERROR/g),
    applyExpandTo('line', 1),
    applyMerge(),
    applyInvert()
)
```

## Create ranges from the document

Use `rangesForMatch()` when document text directly identifies annotations:

```js
rangesForMatch(/\b(?:ERROR|WARNING)\b/g)
```

Regular expression ranges carry the `RegExpExecArray` in `data`, including capture groups. String matches carry the matched string.

Use `rangesForLines()` for geometry based on line boundaries:

```js
rangesForLines('line')             // includes the newline
rangesForLines('line-content')     // excludes the newline
rangesForLines('line-start')       // zero-width point
rangesForLines('line-content-end') // zero-width point
```

Line numbers are stored as one-based range data.

Use `rangesFrom()` to normalize application-owned ranges or document points:

```js
rangesFrom(diagnostics)
rangesFrom('document')
rangesFrom('document-start')
rangesFrom('document-end')
```

## Supply ranges at render time

Render options let one pipeline process changing selections, diagnostics, or view modes:

```js
const pipeline = string()
    .addLayer(
        rangesFromOptions('selection'),
        content => `[${content}]`
    );

pipeline.render(document, {
    selection: [{ start: 6, end: 11 }]
});
```

The callback form can choose a source:

```js
rangesFromOptions(options => {
    if (options.detail === 'full') {
        return rangesFrom('document');
    }

    return rangesFromLayer('summaries');
})
```

Returning `null` or `undefined` produces no ranges.

## Transform geometry

Geometry transformers preserve or derive positions without rescanning rendered output.

### Expand

`applyExpandTo()` aligns ranges to line or document boundaries and can add context lines:

```js
rangesCompose(
    rangesFromLayer('errors'),
    applyExpandTo('line', [1, 2])
)
```

This keeps one line before and two lines after each error.

### Collapse

`applyCollapseTo()` turns intervals into points for insertions:

```js
rangesCompose(
    rangesFromLayer('diagnostics'),
    applyCollapseTo('end')
)
```

Data is retained, so an insertion hook can render a suggestion derived from the diagnostic.

### Fit horizontally

`applyFitToWindow(size, allowTrimming?)` expands a range within its line up to a character width. Oversized single-line ranges are trimmed from the right unless trimming is disabled. Multiline input is always reduced to its first line:

```js
rangesCompose(
    rangesFromLayer('matches'),
    applyFitToWindow(80)
)
```

It is a horizontal line viewport, not a `{ before, after }` context API.

### Merge and invert

`applyMerge()` unions overlapping or adjacent selection geometry, clears top-level data, and records the contributing input records in `origin`. `applyInvert()` returns gaps around a non-empty input:

```js
rangesCompose(
    rangesFromLayer('matches'),
    applyExpandTo('line', 2),
    applyMerge(),
    applyInvert()
)
```

This is the standard omitted-region source for excerpts. `applyInvert()` deliberately produces no output when its input is empty, so a no-match query does not hide the complete document.

## Filter and order ranges

Operation callbacks receive the current range and context with the document, line helpers, render options, the complete operation input, and current index.

```js
rangesCompose(
    rangesFromOptions('diagnostics'),
    applyFilter((range, { renderOptions }) =>
        range.data.severity === renderOptions.severity
    ),
    applySort((a, b) => a.start - b.start),
    applyTake(10)
)
```

Use filtering for semantic selection, sorting when an operation depends on custom order, and `applyTake()` to limit a stream after optional predicate selection.

## Transform data

`applyDataMap()` preserves geometry and replaces each range's data:

```js
rangesCompose(
    rangesForMatch(/^(#{1,6})\s+(.+)$/gm),
    applyDataMap(range => {
        const [, hashes, text] = range.data;

        return {
            level: hashes.length,
            text
        };
    })
)
```

Because the semantic payload changes, `applyDataMap()` clears origin. If the new data still needs the input identity, include the relevant value in the new data explicitly or use a geometry-producing operation with origin tracking.

`applyMap()` is the general one-to-many primitive:

```js
rangesCompose(
    rangesFromLayer('headings'),
    applyMap((range, createRange) => {
        createRange(range.start, range.start, {
            kind: 'anchor',
            heading: range.data
        });
        createRange(range.start, range.end, {
            kind: 'heading',
            heading: range.data
        });
    })
)
```

Every range emitted by `applyMap()` receives the current input range as origin, or preserves that input's existing origin when present.

`applyAugment()` is similar but also passes every original range through unchanged. Use it when derivatives supplement rather than replace the input set.

## Combine sources

`rangesConcat()` evaluates every source and concatenates their ranges:

```js
rangesConcat(
    rangesFromLayer('errors'),
    rangesFromLayer('warnings')
)
```

It does not merge geometry. Apply `applyMerge()` when the combined ranges should become a union.

`rangesWithFallback()` selects the first source that produces output:

```js
rangesWithFallback(
    rangesFromOptions('insertAt'),
    rangesForMatch('<!-- generated -->'),
    rangesFrom('document-end')
)
```

The transformer form `applyFallback()` uses the current composition result first, then configured fallback sources.

`applyAppend()` adds independent sources to a transformed stream. `applyFork()` passes original ranges through and appends one transformed branch after applying its configured same-data-type transformers left-to-right. Use a separate layer or direct data-changing transformer when the derivative needs a different data type.

## Build projections

An annotation-preserving excerpt usually has two layer roles:

```js
const pipeline = html()
    .addLayer(matchSource, matchHooks, 'matches')
    .addLayer(
        rangesCompose(
            rangesFromLayer('matches'),
            applyExpandTo('line', 1),
            applyMerge(),
            applyInvert()
        ),
        rangeHooksHide()
    );
```

The first layer defines interesting content and still renders it. The second derives omitted regions and replaces them during the same traversal. See [Projections and Excerpts](projections-and-excerpts.md).

## Work with points

Point ranges have `start === end`. They can insert labels, suggestions, generated sections, and line prefixes without consuming source text.

Sources for points include:

- `rangesFrom('document-start')` and `rangesFrom('document-end')`
- `rangesForLines('line-start')`, `'line-end'`, and `'line-content-end'`
- `applyCollapseTo()` applied to any interval source

Use `replace` to materialize an insertion:

```js
pipeline.addLayer(
    rangesForLines('line-start'),
    { replace: ({ data: line }) => `${line}: ` }
);
```

## Work with provenance

Origin connects derivative ranges to the source annotations that produced them. Common patterns are:

- expansion or collapse retaining one root source range;
- `applyMap()` producing several derivatives with the same origin;
- `applyMerge()` aggregating several source ranges into an origin array;
- generated point ranges carrying the data needed to build a summary or appendix.

For example, collapsing enriched heading ranges to the document start and merging them produces one insertion range whose `origin` array contains the headings. A `replace` hook can render a table of contents from that array.

Origin is lineage, not a guarantee that derivative and source geometry match. Consult the quick-reference matrix before relying on it across a transformation chain.

## Composition or a custom generator?

Prefer built-in composition when the operation can be stated as selection, geometry transformation, combination, or data mapping. It keeps origin behavior and edge cases visible and independently testable.

Write a custom generator when:

- range generation requires a parser or external analyzer;
- several outputs need one shared scan of the document;
- the policy depends on domain state that does not fit a range callback;
- a budget or ranking algorithm must reason about the set globally.

A custom source can still feed built-in transformers. Keep analysis and subsequent geometry separate when doing so makes the pipeline easier to inspect.

## Common compositions

| Goal | Composition |
|---|---|
| Context around matches | `rangesForMatch -> applyExpandTo` |
| One viewport for nearby matches | `... -> applyMerge` |
| Omitted regions | visible ranges `-> applyInvert` |
| Insert after annotations | `rangesFromLayer -> applyCollapseTo('end')` |
| Add derivatives beside originals | `... -> applyAugment` or `applyFork` |
| First available insertion point | `rangesWithFallback` |
| Progressive detail | `rangesFromOptions -> selected source -> projection` |
| Aggregate source annotations | derive points `-> applyMerge -> origin[]` |
