# Core Concepts

HiText processes text in three stages:

```text
Document text
    -> generate ranges from layers
    -> resolve range hooks
    -> render segments into an output buffer
```

The source document remains unchanged throughout this flow. Layers describe annotations and transformations in source coordinates; the renderer decides how those descriptions become output.

## Document and coordinates

The document is the string passed to a pipeline method:

```js
pipeline.render(document, renderOptions);
```

All range offsets are zero-based, and `end` is exclusive:

```js
const document = 'Hello world';
const range = { start: 6, end: 11 };

document.slice(range.start, range.end);
// world
```

Every layer uses this same coordinate space, even when earlier layers add markup or later layers hide source text. Output positions are not range positions.

`LineBoundaries` provides line and column operations over the document. Line and column numbers returned by it are one-based.

## Ranges

A range identifies an interval in the document and may carry data and origin information:

```ts
type RangeRecord<Data> = {
    start: number;
    end: number;
    data?: Data;
    origin?: RangeRecord<Data> | RangeRecord<Data>[];
};
```

A range value can use record or tuple form:

```js
{ start: 0, end: 5, data: { kind: 'keyword' } }
[0, 5, { kind: 'keyword' }]
```

A range with `start === end` is a point. Point ranges are useful for insertions such as line numbers, labels, and generated blocks.

During generation, HiText normalizes range values into generated records. A generated range also has a `type` carrying the layer marker that associates it with the layer's hooks.

## Stand-off annotations

Ranges are stand-off annotations: they are stored separately from the source text instead of being embedded into it. This allows independently produced ranges to overlap without coordinating their markup.

```text
diagnostic:       [-----------)
search:                [---------)
document:     The answer is unavailable
```

Both providers describe the original document. HiText resolves the crossing intervals when it renders them.

## Range sources

A layer accepts a range source: either an iterable of range values or a generator function:

```js
const staticRanges = [[0, 5], [12, 17]];

function numberRanges(document, createRange) {
    for (const match of document.matchAll(/\d+/g)) {
        createRange(match.index, match.index + match[0].length, match[0]);
    }
}
```

Built-in sources cover matches, lines, raw input, render options, and ranges generated by previous layers. See [Range Functions Reference](range-functions-reference.md).

## Range transformers

A range transformer is a curried function: it receives a range source and returns a new generator. `rangesCompose()` applies transformers from left to right:

```js
rangesCompose(
    rangesFromLayer('matches'),
    applyExpandTo('line', 1),
    applyMerge(),
    applyInvert()
)
```

Transformers can change geometry, filter ranges, map data, combine ranges, or produce derivatives. Their cardinality varies: one input range may produce zero, one, or many outputs, and some operations aggregate the complete input set.

## Data and origin

`data` is application metadata. Hooks and range operations can use it to select behavior without recovering information from rendered text.

`origin` records the source range or ranges from which a derivative was produced. This supports provenance through operations such as expansion, collapse, mapping, and merging. It is not an output coordinate mapping; it is lineage within the source range model.

Origin behavior differs by transformer. The [Range Functions Reference](range-functions-reference.md#quick-reference) states whether each operation inherits, creates, aggregates, or clears origin.

## Layers

A layer combines three things:

```text
range source + range hooks + optional name
```

```js
const nextPipeline = pipeline.addLayer(ranges, hooks, name);
```

A layer created through `addLayer()` receives a unique symbol marker. Generated ranges use that marker to resolve the layer's hooks during rendering. Low-level `PipelineLayer` records may supply another `RangeMarker` and are responsible for its identity.

Names make previous layer results addressable through `rangesFromLayer(name)`. Layers are evaluated in order, so dependencies can point only to layers that have already been added.

## Immutable pipelines

`addLayer()` returns a new pipeline node. It does not mutate the previous one:

```js
const base = html();
const withSearch = base.addLayer(searchRanges, searchHooks, 'search');
const withDiagnostics = withSearch.addLayer(diagnosticRanges, diagnosticHooks);
```

This makes a configured prefix reusable and keeps dependencies explicit. A pipeline itself can also be reused across documents and render options.

The complete pipeline flow is:

1. Generate and normalize ranges for each layer.
2. Make completed layer ranges available by marker and name.
3. Resolve hook definitions for the selected renderer.
4. Sort and segment renderable ranges.
5. Execute hooks and materialize the output buffer.

## Range hooks

Range hooks define rendering semantics:

- `open(context)` emits before a segment.
- `close(context)` emits after a segment.
- `wrap(content, context)` receives a segment's rendered child content.
- `text(documentChunk, context)` transforms source text chunks.
- `replace(context)` substitutes a range and skips its covered source text.
- `break` changes how a range interrupts surrounding ranges.

A function used directly as a hook definition is shorthand for `wrap`:

```js
content => `<mark>${content}</mark>`
```

See [Range Hooks](range-hooks.md) for lifecycle and context details.

## Ranges and segments

A range is an input annotation. A segment is the portion of that range rendered between interruptions.

```text
A: [----------)
B:      [----------)

A segments: [----) [-----)
B segment:       [----------)
```

Crossing ranges cannot be represented directly as a nested output tree. HiText temporarily closes and reopens ranges at the crossing boundary, creating renderable segments.

In hook context:

- `range.start` and `range.end` identify the original generated range.
- `start` and `end` identify the current render segment.
- `rangeIndex` remains stable for all segments of one generated range.

Hooks may therefore run more than once for one range.

## Render buffers

A renderer supplies a buffer with two operations:

```ts
interface RenderBuffer<T, R> {
    append(child: string | T | R): void;
    emit(): R;
}
```

The renderer creates a root buffer. A `wrap` hook causes rendering to use a child buffer for the segment, then passes the emitted child result to the hook and appends its result to the parent.

String, DOM, and JSX outputs use the same traversal. They differ in their buffer implementation and renderer-level text handling.

## Decoration and projection

Decoration preserves the complete source text and changes its representation. Highlighting is a decoration.

Projection builds a derived output view. It may select, omit, replace, reorder, or aggregate document content and may insert synthetic content, while annotations retain document-relative coordinates.

```text
interesting ranges
    -> expand context
    -> merge visible windows
    -> invert
    -> replace omitted regions
```

Because projection happens during the same traversal as annotation rendering, it does not need to cut completed markup or repair output trees. See [Projections and Excerpts](projections-and-excerpts.md).

## Pipeline products

A pipeline exposes several observable stages:

```js
pipeline.ranges(document, renderOptions);
pipeline.rangeHooksDefinitionMap();
pipeline.rangeHooksMap();
pipeline.render(document, renderOptions);
```

These are useful for testing and introspection. Range generation and rendered output can be verified independently.

## Scope

HiText is not a parser, editor, markup language, or syntax highlighter. Those systems can produce ranges or consume output, but HiText's responsibility is composing range-based annotations and transformations into a chosen output representation.
