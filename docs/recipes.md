# Recipes

These recipes emphasize one composition at a time. All ranges remain in source document coordinates, even when a recipe hides or inserts output.

## Highlight matches

```js
import { html, rangesForMatch } from 'hitext';

const highlight = html().addLayer(
    rangesForMatch(/TODO|FIXME/g),
    content => `<mark>${content}</mark>`
);

highlight.render('TODO now, FIXME later');
// <mark>TODO</mark> now, <mark>FIXME</mark> later
```

With a regular expression, `range.data` is the corresponding `RegExpExecArray`. With a string pattern, it is the matched string.

## Combine independent layers

```js
const output = html()
    .addLayer(
        rangesForMatch(/const|return/g),
        content => `<span class="keyword">${content}</span>`
    )
    .addLayer(
        rangesForMatch('value'),
        content => `<mark>${content}</mark>`
    )
    .render('const value = () => return value');
```

Each matcher reads the original document. Neither layer sees or parses markup emitted by the other.

## Style terminal values by data

```js
import { rangesForMatch, tty } from 'hitext';

const report = tty().addLayer(
    rangesForMatch(/error|warning/g),
    tty.createStyleMap({
        error: ['red', 'bgWhite'],
        warning: ['yellow', 'bgBlack']
    })
);

report.render('error & warning');
```

For record data, pass a fetcher as the second argument to `createStyleMap()`.

## Show matches with surrounding lines

```js
import {
    applyExpandTo,
    applyInvert,
    html,
    rangeHooksHide,
    rangesCompose,
    rangesForMatch,
    rangesFromLayer
} from 'hitext';

const snippets = html()
    .addLayer(
        rangesForMatch(/error/gi),
        content => `<mark>${content}</mark>`,
        'matches'
    )
    .addLayer(
        rangesCompose(
            rangesFromLayer('matches'),
            applyExpandTo('line', 2),
            applyInvert()
        ),
        rangeHooksHide()
    );
```

Overlapping context windows are treated as one visible region by inversion. Match annotations remain active inside visible lines.

## Highlight several match classes in one viewport

```js
import { rangesConcat } from 'hitext';

const report = html()
    .addLayer(
        rangesForMatch(/error/gi),
        content => `<span class="error">${content}</span>`,
        'errors'
    )
    .addLayer(
        rangesForMatch(/warning/gi),
        content => `<span class="warning">${content}</span>`,
        'warnings'
    )
    .addLayer(
        rangesCompose(
            rangesConcat(
                rangesFromLayer('errors'),
                rangesFromLayer('warnings')
            ),
            applyExpandTo('line', 1),
            applyInvert()
        ),
        rangeHooksHide()
    );
```

`rangesConcat()` combines sources without changing their geometry. The derived viewport depends on both named layers.

## Add line numbers

```js
import { html, rangesForLines } from 'hitext';

const numbered = html().addLayer(
    rangesForLines('line'),
    {
        open: ({ line }) => `<span data-line="${line}">`,
        close: () => '</span>'
    }
);
```

`rangesForLines('line')` includes each line's newline. For insertion-only prefixes, use `rangesForLines('line-start')` with `replace`:

```js
html().addLayer(
    rangesForLines('line-start'),
    { replace: ({ data: line }) => `${line}: ` }
);
```

Line numbers are stored as one-based range data.

## Insert generated content at the document end

```js
import { rangesFrom, string } from 'hitext';

const withFooter = string().addLayer(
    rangesFrom('document-end'),
    { replace: () => '\nGenerated by HiText' }
);
```

Document start/end sources produce zero-width ranges, so the source text is preserved.

## Redact sensitive spans

```js
import { rangesForMatch, string } from 'hitext';

const redact = string().addLayer(
    rangesForMatch(/token=\w+/g),
    { replace: () => 'token=[redacted]' }
);
```

Contained annotations are skipped with the replaced text. Keep secret values out of hook output and logs.

## Inspect generated ranges in tests

```js
const pipeline = html().addLayer(
    rangesForMatch(/\d+/g),
    content => `<var>${content}</var>`,
    'numbers'
);

const ranges = pipeline.ranges('a1 b22');
const output = pipeline.render('a1 b22');
```

Assert ranges when testing selection and transformation geometry. Assert output when testing hooks, escaping, segmentation, or renderer behavior.
